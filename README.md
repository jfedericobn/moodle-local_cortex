# local_cortex

Moodle plugin that links a course to the **Cortex** knowledge engine. When a
privileged user enables Cortex for a course, the plugin silently builds a
**content-only** `.mbz` backup (no user data) and submits it asynchronously to
Cortex for ingestion. Completion is delivered via a signed, **one-time callback
URL**, with a mandatory polling safety net.

- Target: Moodle 5.3dev / PHP 8.4.
- Component: `local_cortex`.

## Flow

```
enable (web) --> queue adhoc submit_course
submit_course: acquire slot -> content-only backup -> size guard
             -> mint one-time callback URL -> POST /api/v1/ingest/sources (202)
             -> bind job_id, release slot
Cortex worker --> POST {base}/local/cortex/callback.php?token=OTT  (signed)
             --> verify HMAC + consume token -> mark ready/failed
poll_job (safety net) --> GET /api/v1/ingest/jobs/{id} at +15m/+30m/+1h/+2h
```

## What gets sent

`POST {ingesturl}/api/v1/ingest/sources`:

- `source_type: moodle_mbz`, `format: mbz`, `minimization_asserted: true`
- `external_corpus_id: moodle-course-{courseid}`
- `content_base64`: the `.mbz` bytes
- `callback.url`: the minted one-time URL

The content-only backup forces `users=0` and disables all user-data settings.
If user data cannot be forced off, the submission is aborted.

## The eight hardenings (all implemented)

1. **Idempotent submit** — if Cortex answers `ready`/`failed` (unchanged content),
   the row is updated immediately, the token is abandoned, and no callback is awaited.
2. **Required poll safety net** — `poll_job` runs at +15m/+30m/+1h/+2h (max 5) and
   shares `course_state::apply_terminal_state()` with the callback (idempotent on `job_id`).
3. **Raw-body HMAC** — `callback.php` verifies `hash_hmac` over the exact `php://input`
   bytes with `hash_equals`. Cortex transmits exactly the bytes it signs (see below).
4. **No-login webhook** — `callback.php` defines `NO_MOODLE_COOKIES`, is POST-only, and
   uses no `require_login`/sesskey.
5. **Content-only matrix** — fixed backup setting matrix; `users` forced off or the job fails.
6. **Size guard** — `maxmbzbytes` (default 32 MiB); oversize -> `mbz_too_large`, no POST.
7. **Dual-network settings** — `ingesturl` (Moodle->Cortex) and absolute `callbackbase`
   (Cortex->Moodle); connectivity is pinged on settings save.
8. **Durable path** — shipped under `plugins/local_cortex/` so the container sync survives
   core reclones.

> Cortex dependency: `callbacks.py` sends the callback body as the exact
> canonical bytes it signs (`json.dumps(sort_keys=True, separators=(",",":"))`),
> so raw-body HMAC verification is valid. Set `CALLBACK_DISPATCH_MODE=http` and a
> shared `CALLBACK_SIGNING_SECRET`.

## Install / configure

1. Deploy the plugin (this repo syncs `plugins/local_*` into `public/local/*`).
2. Visit **Site administration > Notifications** to install the tables and service.
3. Configure **Site administration > Plugins > Local plugins > Cortex knowledge**, or
   set the `CORTEX_*` variables in `.env` (see `.env.template`) to seed them on startup.
4. Per course: **Course > (More) > Cortex knowledge**, tick *Use Cortex knowledge for
   this course*, save. Use **Resync now** to resubmit.

Required site settings: `ingesturl`, `tenantid`, `callbacksecret`, `callbackbase`,
`callbacktokenttl`, `maxconcurrent`, `maxmbzbytes`.

## Tests

- `tests/hmac_test.php` — golden vector generated by Cortex's `sign_callback_payload`.
- `tests/backup_matrix_test.php` — asserts the content-only setting matrix.
